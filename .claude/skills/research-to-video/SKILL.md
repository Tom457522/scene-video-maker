# 調査レポートから解説動画を作る

レポートをそのまま変換すると「文字のスライドが流れるだけ」の動画になる。
必ず **レポート → 台本(動画のための書き直し)→ 検査と見直し → 書き出し** の順に進める。

## 0. 準備(最初に 1 回)

- 音声合成(どちらも無料)。`npm run make` が自動で選ぶ(`--voice auto`)。
  - **VOICEVOX**: アプリを起動しておけば使える(声が自然)。公開するときは説明欄に「VOICEVOX:話者名」のクレジットが必要(`make` が説明文のファイルに入れる)。
  - **Open JTalk**: `open_jtalk` コマンド。Ubuntu なら `sudo apt install open-jtalk open-jtalk-mecab-naist-jdic hts-voice-nitech-jp-atr503-m001`。
- クラウドのコンテナでは `export REMOTION_BROWSER_EXECUTABLE=$(ls -d /opt/pw-browsers/chromium_headless_shell-*/chrome-headless-shell-linux64/chrome-headless-shell | head -1)`。
- 部品ごとの文字数・個数の上限は `npm run make -- --spec` で見られる。

## 1. 設計メモを作る(台本を書く前に、頭の中かメモで)

1. **だれに・何を持ち帰ってもらうか** を 1 文で決める(例: 「空き家は増え続けていて、相続登記の義務化で他人事でなくなった」)。
2. **論点は 3 つまで**。レポートの残りは捨てる(捨てた情報は、必要なら動画の説明に回す)。
3. **使う数字を選ぶ**。レポートに書いてある数字を、**単位まで同じ形で**使う(「448万戸」を「448」にしない)。それぞれの出典もメモする。
4. **つかみ** を決める: いちばん意外な数字か、視聴者が答えたくなる問い。

## 2. 台本の組み立て(8〜14 シーン、1〜3 分)

| 順 | 役目 | 向いている部品 |
|---|---|---|
| 1 | タイトル(何の動画か) | title |
| 2 | つかみ(意外な数字・問い) | number / qa |
| 3 | なぜ大事か・全体像 | line / bars / pie / image |
| 4〜 | 論点 1〜3(1 論点 1〜3 シーン) | 下の「部品の選び方」 |
| 終盤 | 注意点・反対の意見・限界 | compare / bullets / qa |
| 最後 | まとめ(論点と 1 対 1 に対応させる) | summary |

**同じ部品を 3 つ続けない。箇条書き(bullets)は全体の 4 割まで。**

### 部品の選び方

| 内容 | 部品 | 書き方 |
|---|---|---|
| 1 つの印象的な数字 | number | `!! 約900万戸 説明` |
| 時間による変化 | line | `## 〜の推移` + `2020年: 10万人` |
| 量の比較 | bars | `ラベル: 92%` |
| 内訳・割合 | pie | `## 〜の割合` + `ラベル: 40%` |
| 2 つの対比 | compare | 2 列の表、または `{part=compare}` + `- 名前: 項目` |
| 3 列以上のデータ | table | 表 |
| 出来事の順 | timeline | `2015年: 出来事`(右側は文) |
| 仕組み・手順(5 個まで) | flow | `1. 手順` |
| 手順(6〜8 個)・行動の呼びかけ | steps | `{part=steps}` + `1. 手順` |
| 特徴・理由・利点を並べる | icons | `- [アイコン] 名前: 説明`(アイコン名は `npm run make -- --spec` の icons) |
| 疑問に答える | qa | `Q: 質問` / `A: 答え`(専用の `##` を作る) |
| 発言・定義の引用 | quote | `>> 文` / `-- 出典` |
| 構造・関係の図 | image | 自分で SVG を描き `![説明](図.svg)`(下の「図を描く」) |

部品を確実に決めたいときは見出しに `{part=部品名}` を付ける(推測より優先)。

## 3. 台本の書き方

```markdown
# 増え続ける空き家
900万戸の家に、だれも住んでいない
ナレーション: 日本の空き家問題を、数字と制度から 2 分で整理します。

## 増える 4 つの理由 {part=icons}
- [users] 相続: 子は別の場所に住む
- [coins] 解体費: 100万〜200万円程度
- [file] 税の特例: 土地の税が最大6分の1
- [building] 新築: 人口減でも建ち続ける
出典: 総務省「令和5年住宅・土地統計調査」
ナレーション: 増える理由は 4 つです。▶相続しても、子どもは別の所に住んでいる。▶解体には100万から200万円ほどかかる。▶家があれば、土地の税が最大6分の1になる。▶そして、人口が減っても新築は建ち続けています。
```

- **画面とナレーションを分ける**(いちばん大事)。
  - 画面: 見出しは結論を短く(20 字以内)。項目はキーワードと数字だけ(1 項目 20 字以内、1 画面 3〜5 項目、合わせて 100 字以内)。
  - ナレーション: 話し言葉で、1 シーン 60〜150 字(20 秒以内)。画面の文を読み上げるのではなく、画面を補う。
- **▶** はナレーションの中で「ここで次の項目を出す」印。項目の数と同じ数だけ、その項目を話し始める所に置く(省くと語を手がかりに自動で置くが、明示したほうが確実)。
- **`{表記|よみ}`** で読み方を指定する(固有名詞・略語・読み間違えやすい語。例: `{空家法|あきやほう}`、`{GPT|ジーピーティー}`)。
- **`出典: 〜`** はデータ・数字のシーンには必ず付ける(画面の右下に小さく出て、動画の説明にもまとめられる)。
- `> 字幕` は使わない(ナレーションの字幕が自動で出るので重なる)。
- 強調したい語は `[[語]]`。1 画面に 1〜2 か所まで。

## 4. 図を描く(仕組みの説明があるとき)

箇条書きでは伝わらない「関係・構造・流れ」は、SVG で図を描いて image のシーンにする。

- `viewBox="0 0 1600 900"`、白い背景、文字は 40px 以上、色は 3 色まで。
- 1 枚の図で言うことは 1 つ。ラベルは 8 字以内。
- `<script>` や外部の画像・フォントは使わない(`npm run make` が PNG にするときに無視される)。
- 原稿と同じフォルダに置き、`![説明](図.svg)` と書く(`--images` でフォルダを指定してもよい)。

## 5. 検査と見直し(合格するまで繰り返す。3 回まで)

```bash
npm run make -- 台本.md --source レポート.md --review review --check-only --json
```

結果の JSON を上から順に直す:

1. `error` / 終了コード 1: 書き方の誤り。メッセージどおり直す。
2. `facts.problems`(終了コード 3): **レポートにない数字**。台本の数字をレポートに合わせる(単位も同じに)。丸めた数には「約」を付ける。レポートにない数字は使わない。
3. `issues`(終了コード 2): 文字のはみ出し。文を短くする。
4. `notes`: 切り詰め・分割。項目を減らすか見出しを分ける。
5. `quality.items`: 組み立ての問題。**`score` が 90 以上**になるまで直す。

次に、**静止画を目で見て**直す(`review/一覧.png` と `review/NN-部品.png` を Read で見る)。
`review/見直し.md` の「静止画を見て確かめること」の 6 項目を各 1〜5 点で採点し、3 点以下のシーンを直す。
直したら、同じコマンドをもう一度実行する。

## 6. 書き出し

```bash
npm run make -- 台本.md --source レポート.md --out out/<名前>.mp4 --json
```

- 隣に字幕(`.srt`)と動画の説明(`.txt`: 目次・出典・クレジット)もできる。
- オプション: `--bgm calm|bright|none|<ファイル>`、`--speaker <番号>`(VOICEVOX)、`--speed 1.1`、`--theme light`、`--format 1080p|vertical`、`--subtitles off`、`--sfx off`。
- 書き出したら、MP4・字幕・説明のパスと、`quality.score`、VOICEVOX を使ったならクレジットを書く必要があることを伝える。

見本: `examples/空き家/レポート.md`(調査レポート)と `examples/空き家/台本.md`(それから書いた台本)。
