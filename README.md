# シーン式 解説動画メーカー

文字を入力するだけで、アニメーション付きの解説動画(MP4)を作れるローカル Web アプリです。
動画は「シーンの並び」で、1 シーン = **部品の種類 + 入力した文字 + 秒数**。動きの速さやタイミングは部品が決めるので、ユーザーは文字・秒数・並び順だけを触ります。

- TypeScript / React / Vite / [Remotion](https://www.remotion.dev/)
- プレビューは `@remotion/player`、書き出しはローカルの Node から `@remotion/renderer`
- 1280 × 720 / 30fps / 音声なし(書き出し時に 1080p と縦長 9:16 も選べます)
- 外部サーバー・課金サービス・AI は使いません(このパソコンの中だけで動きます)

## 必要なもの

- Windows 10 / 11(macOS・Linux でも動きます)
- [Node.js](https://nodejs.org/) 20.19 以上 または 22.12 以上(22 LTS 推奨)

## 起動

**Windows**: フォルダの中の `start.bat` をダブルクリックします(初回は `npm install` も自動で行います)。

**コマンドで起動する場合**:

```bash
npm install
npm run dev
```

ブラウザで http://127.0.0.1:5173 が開きます(開かなければ手で開いてください)。最初は `projects/sample.json` が開きます。
起動すると裏で書き出しの準備(バンドル作成など)を始めるので、最初の書き出しも待たずに始まります(`SCENE_NO_PREBUNDLE=1` で止められます)。

> **初回の書き出しについて**: MP4 の書き出しには Chrome Headless Shell を使います。初めて使うときに一度だけ自動でダウンロードされます(インターネット接続が必要)。すでにある Chrome / Chromium を使いたいときは、環境変数 `REMOTION_BROWSER_EXECUTABLE` にその実行ファイルのパスを入れて起動してください。

## 画面の使い方

いつも見えるのは毎回使うものだけで、ほかの機能は使う場面で出てきます。流れは「① 内容を書く → ② プレビューで確かめる → ③ 動画にする」です。

| 場所 | できること |
|---|---|
| 上部 | 左から「☰ プロジェクト名」(メニュー)、動画のタイトル(クリックして書き換え)、シーンの数と長さ、元に戻す / やり直し、保存の状態、直したほうがよいところがあれば「確認 N 件」、「▶ 動画にする」 |
| 左 | シーンの一覧(見どころの縮小画像つき)。ドラッグで並べ替え。選んだシーン(とカーソルを当てたシーン)にだけ、コピー・複製・削除のボタンが出る。右上の「…」で、すべてのシーンをコピー・文字をまとめて置き換え。下の「+ シーンを追加」 |
| 中央 | プレビュー。再生/停止、シークバー、上の番号でシーンの頭出し。動画の上の「繰り返し」で選んだシーンだけを繰り返し、「縦長で見る」で縦長の見え方に切り替え、「大きく見る」でシーンの一覧を隠してプレビューを広げる。「キー操作の一覧」(? キー) |
| 右 | 「このシーン」タブ: いちばん上に文字の入力欄、「種類を変える」。秒数・章の区切り・画像(PNG)での書き出しは「詳しい設定」に折りたたんである(秒数が短い・文字が小さいときは上に注意が出る)。「動画全体」タブ: テーマ・章の表示・チャンネル名・ロゴ・エンドカード・シーンの切り替え・BGM(自動で作る曲か、「曲を追加」で手持ちの MP3 などを選ぶ) |

シーンが 1 つもないときは、中央に「文章を貼って作る / ひな形から作る / 1 シーンずつ作る」の 3 つが出ます。

### メニュー(左上の ☰)

| まとまり | 項目 |
|---|---|
| 動画を開く | 保存してある動画の一覧 / 新しい動画を作る |
| この動画 | 名前を変える / コピーして別の動画にする / 前の版に戻す |
| ほかの PC とやりとり | zip で持ち出す(画像も入る)/ zip から読み込む |
| そのほか | 画像の整理 / この動画を削除 |

### 「+ シーンを追加」

| タブ | 内容 |
|---|---|
| 種類から選ぶ | 全種類を縮小画像つきのカードで並べる。「文字で伝える / 手順・流れ / 数字・データ / 比べる・見せる」で絞り込める。カーソルを当てると動きが流れる |
| 文章から作る | 下の「文章からシーンを作る」の書き方で書いた文章を、シーンの並びにする |
| 貼り付け | コピーしたシーン(別の動画でコピーしたものも)を、選んでいるシーンの後ろに入れる |

### キーボード(? キーで一覧が出ます)

| キー | 動き |
|---|---|
| スペース | 再生 / 停止 |
| ↑ ↓ | シーンを選ぶ |
| Alt + ↑ ↓ | シーンを並べ替える |
| Ctrl + D / Delete | シーンを複製 / 削除 |
| Ctrl + C / Ctrl + V | シーンをコピー / 選んでいるシーンの後ろに貼り付け(別のプロジェクトにも貼り付けられる) |
| L | 選んだシーンだけを繰り返し再生 |
| Ctrl + S | すぐに保存して、前の版として残す(ふだんは自動で保存される) |
| Ctrl + Z / Ctrl + Shift + Z(Ctrl + Y) | 元に戻す / やり直し(続けて打った文字は 1 回で戻る) |
| Ctrl + B | 入力欄で選んだ語を `[[ ]]` で囲んで強調(もう一度で外す) |
| ? | キー操作の一覧 |

入力欄の中では、矢印・Delete・スペースなどは文字の入力に使われます(シーンの操作は入力欄の外で)。

### 編集を助ける機能

- **入力はすぐプレビューに反映**されます。シーンを選んだときや、止めて編集しているときは、そのシーンの見どころ(70% 地点)を映します(シーンの頭は登場前で何も映っていないことが多いため)。
- **強調**: 文の中の `[[語]]` は、その語にマーカーが引かれます。対応している入力欄には「強調」ボタンがあります。
- **確認 N 件**: 秒数が文字数に対して短いシーン・入力に問題があるシーンを上部にまとめて出します。押すと一覧が開き、そのシーンへ移ったり「目安に合わせる」で直したりできます。「動画にする」の最初にも同じ一覧が出ます。
- **秒数の目安**: 画面に出る文字数から、読み切るのに必要な秒数を出します(1 秒 10 文字 + 動き 1.5 秒)。目安の 4 分の 3 より短いと警告し、「目安に合わせる」で直せます。
- **文字の大きさの確認**: 選んだシーンでいちばん小さい文字の大きさ(1280×720 の画面での px)を測り、20px 未満なら右の列の上に「小さめ」と警告します。
- **種類を変える**: 入力した文字は、新しい種類にも使える項目だけ引き継ぎます。引き継げなかった項目があれば名前を知らせます(Ctrl+Z で戻せます)。
- **ひな形**: 最初の画面の「ひな形から作る」で、3 分解説・比較レビュー・ニュース風・手順の解説から始められます(`( )` の中を書き換えて使う)。
- **シーンのコピーと貼り付け**: コピーのボタン / Ctrl+C でコピーし、別のプロジェクトでも Ctrl+V(または「+ シーンを追加」→「貼り付け」)で貼り付けられます。
- **位置をプレビューで指す**: 画像の部品の「丸の位置」などは、「🎯 プレビューをクリックして決める」を押してからプレビューの上をクリックして決めます。
- **章の区切り**: 「詳しい設定」の「章の区切り」に章の名前を書くと、そのシーンから新しい章になります(書かなければ見出しから自動で決まります)。
- **文章からシーンを作る**: 次の書き方の文章を貼ると、シーンの並びに変わります(AI は使わず、決まった規則で変換します)。部品の文字数・個数の上限を超えたところは切り詰めて知らせます。1 つの見出しの下に種類の違う書き方(`!!` の数字と `Q:`/`A:` など)を書くと、書いた順に別々のシーンに分けて知らせます。

  | 書き方 | できるシーン |
  |---|---|
  | `# タイトル`(次の行はサブタイトル) | タイトル |
  | `## 見出し` と `- 項目` | 箇条書き(7 個以上は「(続き)」に分ける) |
  | `## 見出し` と `1. 手順` | 流れ図 |
  | `## 見出し` と `ラベル: 92%` | 横棒グラフ |
  | `## 見出し` と `2008年: 出来事` | 年表 |
  | `## まとめ`(要点・ポイント)と `- 項目` | まとめ |
  | `## 〜の割合` と `ラベル: 40%` | 円グラフ |
  | `## 〜の推移` と `2020年: 10` | 折れ線グラフ |
  | `1. 手順` が 6 個以上 | 縦のステップ |
  | `| 左 | 右 |` の表 | 比較 |
  | `| A | B | C |`(3 列以上)の表 | 表 |
  | `![説明](ファイル名)` | 画像 |
  | ` ```js ` 〜 ` ``` ` | コード |
  | `Q: 質問` と `A: 答え` | Q&A |
  | `>> 文` と `-- 出典` | 引用 |
  | `!! 約100万件 説明` | 大きな数字 |
  | `> 文` | そのシーンの字幕 |
  | `ナレーション: 文` | 読み上げる文(下の「ナレーション付きの動画にする」) |
  | `出典: 文` | 画面の右下に小さく出す出典 |
  | `- [shield] 名前: 説明` | アイコン一覧 |
  | `## 見出し {part=steps}` | 部品を直接決める(書き方からの推測より優先) |

- **文字をまとめて置き換える**(シーン一覧の右上の「…」): タイトル・全シーンの入力・チャンネル名・エンドカードの文をまとめて置き換えます(1 回の Ctrl+Z で戻せます)。
- **YouTube の章の時刻**(「動画にする」の下): 各シーンの見出し(または章の区切り)と開始時刻から `0:00 タイトル` の形の文を作り、コピーできます(同じ見出しが続くシーンは 1 章にまとめます。YouTube の条件「3 章以上・各 10 秒以上」を満たさないときは注意が出ます)。
- **字幕ファイル(SRT)**(「動画にする」の下): 各シーンの「字幕」に自分で書いた文を、そのシーンの時間に並べた字幕ファイルを書き出します(YouTube などに上げられます。文を自動で作ることはしません)。

### 保存と安全のしくみ

- **自動で保存**: 変更が止まって少し(1.5 秒)たつと、`projects/<名前>.json` に自動で保存します。上部に「自動で保存済み」と出ます。Ctrl+S を押すと、すぐに保存して前の版としても残します。
- **下書き**: 保存できなかった変更(サーバーが止まっていたなど)は、ブラウザの中(localStorage)にも残ります。次に開いたときに「下書きを復元する / 下書きを捨てる」を選べます。
- **前の版**: 保存するとき、その前の版が `projects/.history/<名前>/` に残ります(最新 30 件。自動で保存するときは 10 分おき、Ctrl+S では毎回)。メニューの「前の版に戻す」で戻せます。
- **削除**はファイルを消さず `projects/.trash/` に移します(履歴も一緒に移ります)。手で戻すこともできます。
- **zip で持ち出す / 読み込む**: プロジェクトと使っている画像を 1 つの zip にまとめ、別の PC に移したり人に渡したりできます。読み込むとき、同じ名前で中身の違う画像があれば名前を付け直します。

### 書き出し

- **動画にする**: 上部右の「▶ 動画にする」を押すと、次の順に並んだ画面が開きます。
  1. 書き出す前の確認(直したほうがよいところ。その場で直せる)
  2. どこで使いますか?(ふつうの動画 = 720p / きれいな動画 = 1080p / ショート = 縦長 / GIF)
  3. ファイルの大きさ(小さめ / ふつう / 大きめ)
  4. 「書き出しを始める」。書き出しは**順番待ち**に入り、1 つずつ順に行います(書き出し中でも編集を続けられ、次を追加できます)。進み具合と残り時間の見込みは、この画面と上部に出ます。書き出したファイルは、この画面の「保存する」でダウンロードでき、`out/` にも残ります。
  5. 下の「ほかの書き出し」: 選んでいるシーンを画像(PNG)で / 字幕ファイル(SRT)/ YouTube の章の時刻 / いくつもの動画をまとめて

  | 形式 | 大きさ | 内容 |
  |---|---|---|
  | ふつうの動画(720p) | 1280×720 | 標準 |
  | きれいな動画(1080p) | 1920×1080 | 720p の画面を 1.5 倍の解像度で撮る(文字や図形はぼやけない) |
  | ショート(縦長) | 1080×1920 | 横長の動画を中央に置き、上にタイトル、下に今の章と進み具合を出す |
  | GIF | 640×360・15fps | 選んでいるシーンだけを、くり返し再生する GIF にする |

  | ファイルの大きさ | 内容 |
  |---|---|
  | 小さめ(`light`) | ファイルが小さい(共有向け) |
  | ふつう(`normal`) | 標準 |
  | 大きめ(`high`) | 高画質でファイルが大きい(保存・再編集向け) |

- **まとめて書き出し**: 「動画にする」→「いくつもの動画をまとめて」で、複数のプロジェクト × 複数の形式を一度に順番待ちに入れられます(編集中のプロジェクトは今の内容、ほかは保存してある内容)。
- **PNG**: 右列の「詳しい設定」か「動画にする」の下から、選んだシーンの見どころを 1 枚の画像で書き出します(サムネイルや資料に)。

### 動画全体の設定(右列の「動画全体」タブ)

| 項目 | 内容 |
|---|---|
| テーマ | ネイビー(標準)/ ライト / ブラック / フォレスト。全部品の色がまとめて変わる |
| 章の表示 | 右上に今の章(見出し)、下の端に章ごとの進み具合を出す |
| チャンネル名・ロゴ画像 | 右上とエンドカードに出す |
| エンドカード | 最後に 4 秒の締めの画面(文・チャンネル名・ロゴ)を付ける |
| シーンの切り替え | 各シーンの終わりの消え方: 左へ流れる / フェード / ワイプ / ズーム / 動きなし |

### 画像

ロゴや画像の部品で使う画像は `projects/assets/` に入ります。入力欄の「画像を追加」から選ぶと、そこにコピーされます(PNG / JPEG / GIF / WebP、10MB まで。SVG は使えません)。フォルダに直接入れても使えます。
メニューの「画像の整理」で、画像ごとに使っているプロジェクトを確かめ、使っていない画像を削除(`.trash` へ移す)できます。

## 部品

| 部品 | 内容 |
|---|---|
| `title` タイトル | 文字が 1 文字ずつ跳ねて登場、下線、サブタイトル、漂う図形 |
| `bullets` 箇条書き | 番号バッジが回転して登場、文が右から入る、`[[ ]]` の語にマーカー |
| `icons` アイコン一覧 | アイコンつきのカードを 2〜6 枚並べる(特徴・メリットの紹介に) |
| `timeline` 年表 | 線が伸び、点と時期・出来事が順に現れる |
| `flow` 流れ図 | ボックスが順に出現、矢印が伸び、粒が行き来する |
| `steps` 縦のステップ | 2〜8 個の手順を縦に並べ、線が伸び、最後に完了の印 |
| `compare` 比較 | 左右のパネルが両側から入り、項目が交互に現れ、真ん中に VS |
| `table` 表 | 2〜4 列の表。行が順に現れ、強調する行に帯 |
| `bars` 横棒グラフ | 横棒が伸びながら数字がカウントアップ |
| `line` 折れ線グラフ | 推移を、線が左から描かれ、点と値が順に出る形で見せる |
| `pie` 円グラフ | 割合・内訳をドーナツ型で。区切りが順に描かれ、凡例に割合 |
| `image` 画像 | 図や写真をゆっくり寄りながら見せ、注目する場所を丸で囲む |
| `number` 大きな数字 | 数字がカウントアップし、枠が描かれる |
| `code` コード | 色分けしたコードが 1 行ずつ現れ、指定した行を強調 |
| `quote` 引用 | 引用符がポンと出て、文が左から現れる |
| `qa` Q&A | 質問のあと、少し間をおいて答えが現れる |
| `summary` まとめ | チェックマークが 1 つずつ描かれる |

アイコンは lucide(ISC ライセンス)から約 50 個を選んで同梱しています。全部品を並べた見本は `projects/部品の見本.json`、または「+ シーンを追加」の「すべての種類の見本」(`/?gallery`)で見られます。エディタの画面では、部品を「シーンの種類」と呼んでいます。

## プロジェクトファイル

1 本の動画 = `projects/<名前>.json` の 1 ファイルです。エディタで保存すると書き出されます。手で書いても構いません。

```json
{ "title": "ブロックチェーン",
  "settings": { "theme": "navy", "chapters": false, "channelName": "", "logo": "", "endCard": false, "endCardMessage": "ご視聴ありがとうございました" },
  "scenes": [
    { "part": "bullets", "seconds": 5.5,
      "props": { "heading": "ブロックチェーンとは", "items": ["取引の記録を[[ブロック]]にまとめる"] } }
  ] }
```

- `part` は部品のフォルダ名、`seconds` は 1〜60 秒、`props` は部品の入力項目です。`settings` は省略でき、省略すると既定値になります。
- `props` に足りない項目や不正な値があっても、部品の既定値で補って表示します(エディタの右列に注意が出ます)。

## コマンド

| コマンド | 内容 |
|---|---|
| `npm run dev` | エディタを起動 |
| `npm run render -- <プロジェクト>` | エディタを使わずに MP4 を `out/<プロジェクト>.mp4` へ書き出す |
| `npm run make -- <原稿.md> [オプション]` | 原稿(「文章からシーンを作る」の書き方)から、はみ出しを調べてから MP4 を作る(下の「原稿から 1 コマンドで動画にする」) |
| `npm run stills -- <プロジェクト> [割合]` | 各シーンの見どころ(既定は 70%)を `stills/<プロジェクト>/` に PNG で書き出し、文字のはみ出し(画面の外・枠の外・文字の重なり)を自動で調べる |
| `npm run stress [-- <部品名>]` | 全部品を、schema の上限いっぱいの入力・最短の秒数・最小の入力で書き出し、はみ出しを自動で調べる |
| `npm run visual [-- --update]` | 見本の静止画を `test/visual/` の基準の画像と比べ、見た目が変わっていないかを調べる(`--update` で基準を更新) |
| `npm run new-part -- <部品名> [表示名]` | 決まりに沿った部品のひな形を作る |
| `npm test` | 単体テスト(`test/*.test.ts`、node:test) |
| `npm run e2e` | エディタの自動操作テスト(`e2e/*.spec.ts`、Playwright)。本物のブラウザでエディタを操作し、書き出しまで確かめる。見本を一時フォルダにコピーして使うので、`projects/` は変わらない |
| `npm run check` | 型チェック(`tsc`)・lint(`eslint`)・単体テスト |
| `npm run studio` | Remotion Studio で開く(部品の開発用) |

`<プロジェクト>` には `sample` のような名前か、JSON ファイルのパスを書けます。stills / stress / visual は、問題があると終了コード 1 で終わります。

## 原稿から 1 コマンドで動画にする

エディタを開かずに、原稿の Markdown(「文章からシーンを作る」と同じ書き方)から MP4 を作れます。ほかのアプリや Claude Code のスキルから動画を自動で作るための入口です。

```bash
npm run make -- 原稿.md --images 図のフォルダ --theme light --quality light --out out/今日の動画.mp4
```

1. 原稿をシーンに変換します(部品の上限を超えたところは切り詰めて知らせます)。
2. 画像のシーン `![説明](ファイル名)` のファイルを `--images` のフォルダ(省略すると原稿と同じフォルダ)から `projects/assets/` に入れます。**SVG はそのままは使わず、ブラウザで白い背景の PNG にしてから入れます**(SVG の中のスクリプトは動きません)。
3. `--source` があれば、原稿の数字が元のレポートにあるかを調べます(ないと **終了コード 3**)。
4. ナレーションを音声にし、BGM と効果音を用意します(下の「ナレーション付きの動画にする」)。
5. 組み立ての質(単調さ・つかみ・まとめ・文字の量・出典など)を検査して点数を出します。
6. 各シーンの見どころを撮って、文字のはみ出しを調べます。はみ出しがあれば **MP4 を作らずに終了コード 2** で終わるので、原稿の文を短くしてやり直します。
7. MP4・字幕(.srt)・動画の説明(.txt)を書き出します。

| オプション | 内容 |
|---|---|
| `--source <ファイル>` | 元の調査レポート。台本の数字がレポートにあるかを調べる(ないと終了コード 3) |
| `--review <フォルダ>` | 見直し用に、各シーンの静止画・全シーンの一覧の画像・見直し.md を書き出す |
| `--images <フォルダ>` | 画像を探すフォルダ |
| `--voice` | `auto`(既定)/ `voicevox` / `openjtalk` / `none`(ナレーションを音声にしない) |
| `--speaker <番号>` | VOICEVOX の話者の番号(既定 3) |
| `--speed <速さ>` | 話す速さ(既定 1.1) |
| `--bgm` | `calm` / `bright` / `none` / 音声ファイル(既定: ナレーションがあれば `calm`) |
| `--bgm-volume <0〜1>` | BGM の音量(既定 0.1。話している間は自動で下がる) |
| `--sfx on\|off` | 項目が出るときの効果音(既定 on) |
| `--subtitles on\|off` | ナレーションの字幕を画面に出す(既定 on) |
| `--format` | `720p`(既定)/ `1080p` / `vertical`(縦長) |
| `--quality` | `light` / `normal`(既定)/ `high` |
| `--theme` | `navy`(既定)/ `light` / `black` / `forest` |
| `--chapters` | 章の表示を付ける |
| `--out <ファイル>` | 書き出す MP4(既定: `out/<原稿の名前>.mp4`)。字幕(`.srt`)と動画の説明(`.txt`: 目次・出典・クレジット)も隣に作る |
| `--project <ファイル>` | 変換したプロジェクト JSON も保存する(`projects/` に置けばエディタで直せる) |
| `--check-only` | 検査だけして、MP4 は作らない |
| `--allow-overflow` | はみ出しがあっても書き出す |
| `--allow-unverified` | レポートにない数字があっても書き出す |
| `--spec` | 部品ごとの入力の上限を JSON で出す(AI が台本を上限内で書くため) |
| `--json` | 結果を JSON 1 行で出す(`ok`・`out`・`srt`・`description`・`seconds`・`notes`・`issues`・`facts`・`quality`) |

プロジェクト JSON を渡すこともできます(`--theme` などは JSON の設定を上書きします)。
SVG を PNG にするときは書き出しと同じ Chrome を使います(環境変数 `REMOTION_BROWSER_EXECUTABLE`、なければ Remotion がダウンロードした Chrome Headless Shell。一度も書き出したことがなければ、先に何か 1 本書き出してください)。

原稿の書き方のこつ(はみ出しにくくする):
- 箇条書きの 1 項目は 25 文字くらいまで、見出しは 20 文字くらいまで。
- `> 字幕` が出るのは、画像・流れ図・縦のステップ・年表・表・グラフ・コード・アイコン一覧だけです(箇条書き・まとめ・タイトルには出ません)。40 文字くらいまで。ナレーションの字幕を出すシーンでは使われません。
- グラフの値には単位まで書く(`2023年: 900万戸`)。`--source` の照合でレポートの数字と比べられます。
- `Q:` / `A:` は、ほかの箇条書きと同じ `##` に入れず、専用の `##` を作る(同じ `##` にあると Q&A のシーンだけになる)。
- 2 列の表は「比較」、3 列以上は「表」になります。用語の一覧は `- [[用語]]:説明` の箇条書きにします。

## ナレーション付きの動画にする

原稿の各 `##` に `ナレーション:` の行を書くと、`npm run make` が音声にして、シーンの秒数を声の長さに合わせます。

```markdown
## 増える 3 つの理由
- 相続しても住まない
- 解体に費用がかかる
- 税の特例がある
出典: 総務省「令和5年住宅・土地統計調査」
ナレーション: 理由は 3 つです。▶相続しても、子どもは別の所に住んでいる。▶解体には費用がかかる。▶そして、{空家法|あきやほう}の前は税の特例が外れなかった。
```

- **▶** の所で、画面の次の項目が出ます(省くと、項目の語がナレーションに出てくる所に自動で置きます)。
- **`{表記|よみ}`** で読み方を指定できます(字幕には表記、声にはよみを使う)。
- 話している文が字幕として画面の下に出ます(本文は少し縮めて場所を空けます。`--subtitles off` で消せます)。
- BGM(その場で計算して作る曲。音源のファイルやライセンスは不要)を流し、話している間は音量を下げます。項目が出るときに小さな効果音も鳴らします。
- 音声は `projects/assets/audio/` に保存し、同じ文なら作り直しません。エディタの「詳しい設定」でもナレーションと出典を書けます(文を変えると音声は外れ、次の `npm run make` で作り直します)。

音声合成は無料のものを使います。どちらかを用意してください(`--voice auto` は VOICEVOX が起動していればそれを、なければ Open JTalk を使います)。

| 音声合成 | 用意 | 声 |
|---|---|---|
| [VOICEVOX](https://voicevox.hiroshiba.jp/) | アプリを入れて起動しておく(Windows / Mac / Linux) | 自然。話者は `--speaker` で選ぶ。**公開するときは「VOICEVOX:話者名」のクレジットが必要**(動画の説明 `.txt` に入る) |
| Open JTalk | Ubuntu: `sudo apt install open-jtalk open-jtalk-mecab-naist-jdic hts-voice-nitech-jp-atr503-m001`(場所は環境変数 `OPEN_JTALK`・`OPEN_JTALK_DIC`・`OPEN_JTALK_VOICE` でも指定できる) | 機械的だが、どこでも動く |

## 調査レポートから動画を作る(AI に頼むとき)

AI に調べてもらった結果をそのまま変換すると、文字が多いスライドが流れるだけになります。Claude Code には、レポートを動画のための台本に書き直してから作る手順(スキル `.claude/skills/research-to-video/SKILL.md`)を入れています。「このレポートを動画にして」と頼むと、次の順に進めます。

1. **台本を書く**: 論点を 3 つに絞り、つかみ(意外な数字)→ 本論 → まとめ の順に 8〜14 シーンにする。画面はキーワードと数字だけにし、説明はナレーションに回す。内容に合わせて部品(数字・グラフ・比較・アイコン・図)を選ぶ。
2. **数字を照合する**(`--source レポート.md`): 台本の数字が、レポートに同じ値であるかを調べる。書き直しの途中で数字が変わったり作られたりするのを防ぐ。
3. **質を検査する**: 同じ部品が続く・つかみやまとめがない・画面の文字が多い・出典がない・ナレーションが長い、などを点数にする(`quality.score`)。
4. **目で見て直す**(`--review フォルダ`): 各シーンの静止画と全シーンの一覧の画像を AI が見て、決まった観点で採点し、低いシーンを直す。
5. **書き出す**: MP4・字幕(.srt)・動画の説明(目次・出典・クレジット)ができる。

見本: [`examples/空き家/レポート.md`](examples/空き家/レポート.md)(調査レポート)から書いた [`examples/空き家/台本.md`](examples/空き家/台本.md)。

```bash
npm run make -- examples/空き家/台本.md --source examples/空き家/レポート.md --review review --out out/空き家.mp4
```

## 部品の足し方

```bash
npm run new-part -- step-list ステップ一覧
```

で `src/parts/step-list/index.tsx` ができ、エディタの一覧とフォームに現れます。本体のコードは変えません(フォルダを置くだけで自動で登録されます)。各部品が公開するのは `meta`(名前・説明・秒数)、`schema`(zod の入力項目)、`Component`(props と frame から描く)の 3 つだけです。

決まり(フレームだけで見た目を決める、色や動きは `src/kit/` を使う など)・kit の使い方・確認手順は **[PARTS_GUIDE.md](PARTS_GUIDE.md)** にまとめています。AI に部品の追加を頼むときも、このガイドを読ませてください。

## CI(自動テスト)

GitHub に push すると、GitHub Actions(`.github/workflows/ci.yml`)が **Windows と Ubuntu** で次を実行します。

1. `start.bat --check`(Windows のみ。起動の手前までを確かめる)
2. `npm run check`(型チェック・lint・単体テスト)
3. `npm run stills -- sample` と `はみ出し確認` の静止画の書き出しと、はみ出しの自動検査
4. `npm run stress`(全部品の最大・最小の入力でのはみ出しの検査)
5. `npm run visual`(Ubuntu のみ。見た目が基準から変わっていないか)
6. `npm run e2e`(エディタの自動操作テスト。画面操作と MP4・PNG の書き出しまで)

書き出した静止画・差分の画像・自動操作テストの結果(失敗したとき)は、実行結果のページの「Artifacts」からダウンロードして見られます。

## しくみのメモ

- エディタは Vite、書き出しは Remotion のバンドラ(webpack)で同じ `src/video/ProjectVideo.tsx` をビルドします。部品の自動登録は、Vite では `import.meta.glob`、webpack では `require.context` で行います(`src/parts/modules.ts`)。Node(コマンドやテスト)では `server/parts-node.ts` がフォルダを見て読み込みます。
- 書き出しのバンドルは `src/` か `projects/assets/` が変わったときだけ作り直します。
- 書き出し中に使う文字のフォント(Noto Sans JP・JetBrains Mono、`@fontsource` から読み込み)が読み終わるまで撮影を待つので、ネットにつながっていなくても文字化けしません。
- テーマは `src/kit/theme.ts` の `colors` が今のテーマの色を返すしくみで、部品のコードを変えずに切り替わります。
- API は `127.0.0.1` だけで待ち受け、別のサイトからの書き込み要求(Origin が違う・Content-Type が JSON でない)は断ります。プロジェクト名・画像のファイル名・書き出したファイル名は、フォルダの外を指せない文字だけを受け付けます。
