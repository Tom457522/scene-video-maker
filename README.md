# シーン式 解説動画メーカー

文字を入力するだけで、アニメーション付きの解説動画(MP4)を作れるローカル Web アプリです。
動画は「シーンの並び」で、1 シーン = **部品の種類 + 入力した文字 + 秒数**。動きの速さやタイミングは部品が決めるので、ユーザーは文字・秒数・並び順だけを触ります。

- TypeScript / React / Vite / [Remotion](https://www.remotion.dev/)
- プレビューは `@remotion/player`、書き出しはローカルの Node から `@remotion/renderer`
- 1280 × 720 / 30fps / 音声なし(書き出し時に 1080p と縦長 9:16 も選べます)
- 外部サーバー・課金サービス・AI は使いません(このパソコンの中だけで動きます)

## 必要なもの

- Windows 10 / 11(macOS・Linux でも動きます)
- [Node.js](https://nodejs.org/) 20.19 以上 または 22.12 以上(22 LTS 推奨)

## 起動

**Windows**: フォルダの中の `start.bat` をダブルクリックします(初回は `npm install` も自動で行います)。

**コマンドで起動する場合**:

```bash
npm install
npm run dev
```

ブラウザで http://127.0.0.1:5173 が開きます(開かなければ手で開いてください)。最初は `projects/sample.json` が開きます。
起動すると裏で書き出しの準備(バンドル作成など)を始めるので、最初の書き出しも待たずに始まります(`SCENE_NO_PREBUNDLE=1` で止められます)。

> **初回の書き出しについて**: MP4 の書き出しには Chrome Headless Shell を使います。初めて使うときに一度だけ自動でダウンロードされます(インターネット接続が必要)。すでにある Chrome / Chromium を使いたいときは、環境変数 `REMOTION_BROWSER_EXECUTABLE` にその実行ファイルのパスを入れて起動してください。

### 編集を助ける機能

- **入力はすぐプレビューに反映**されます。止めているときは、編集中のシーンの見どころ(70% 地点)へ自動で移ります。
- **強調**: 文の中の `[[語]]` は、その語にマーカーが引かれます。対応している入力欄には「強調」ボタンがあります。
- **秒数の目安**: 画面に出る文字数から、読み切るのに必要な秒数を出します(1 秒 10 文字 + 動き 1.5 秒)。目安の 4 分の 3 より短いと警告し、「目安に合わせる」で直せます。
- **文字の大きさの確認**: 選んだシーンでいちばん小さい文字の大きさ(1280×720 の画面での px)を設定欄に出し、20px 未満なら「小さめ」と警告します。長い文が自動で小さくなりすぎていないかが分かります。
- **ひな形**: 「新規」で、3 分解説・比較レビュー・ニュース風・手順の解説のひな形から始められます(`( )` の中を書き換えて使う)。
- **シーンのコピーと貼り付け**: 📋 / Ctrl+C でコピーし、別のプロジェクトでも Ctrl+V(または「📋 貼り付け」)で貼り付けられます。
- **位置をプレビューで指す**: 画像の部品の「丸の位置」などは、「🎯 プレビューをクリックして決める」を押してからプレビューの上をクリックして決めます。
- **章の区切り**: シーンの「章の区切り」に章の名前を書くと、そのシーンから新しい章になります(書かなければ見出しから自動で決まります)。
- **文章からシーンを作る**: 次の書き方の文章を貼ると、シーンの並びに変わります(AI は使わず、決まった規則で変換します)。部品の文字数・個数の上限を超えたところは切り詰めて知らせます。

  | 書き方 | できるシーン |
  |---|---|
  | `# タイトル`(次の行はサブタイトル) | タイトル |
  | `## 見出し` と `- 項目` | 箇条書き(7 個以上は「(続き)」に分ける) |
  | `## 見出し` と `1. 手順` | 流れ図 |
  | `## 見出し` と `ラベル: 92%` | 横棒グラフ |
  | `## 見出し` と `2008年: 出来事` | 年表 |
  | `## まとめ`(要点・ポイント)と `- 項目` | まとめ |
  | `## 〜の割合` と `ラベル: 40%` | 円グラフ |
  | `## 〜の推移` と `2020年: 10` | 折れ線グラフ |
  | `1. 手順` が 6 個以上 | 縦のステップ |
  | `| 左 | 右 |` の表 | 比較 |
  | `| A | B | C |`(3 列以上)の表 | 表 |
  | `![説明](ファイル名)` | 画像 |
  | ` ```js ` 〜 ` ``` ` | コード |
  | `Q: 質問` と `A: 答え` | Q&A |
  | `>> 文` と `-- 出典` | 引用 |
  | `!! 約100万件 説明` | 大きな数字 |
  | `> 文` | そのシーンの字幕 |

- **一括置換**: タイトル・全シーンの入力・チャンネル名・エンドカードの文をまとめて置き換えます(1 回の Ctrl+Z で戻せます)。
- **YouTube の章の時刻**: 各シーンの見出し(または章の区切り)と開始時刻から `0:00 タイトル` の形の文を作り、コピーできます(同じ見出しが続くシーンは 1 章にまとめます。YouTube の条件「3 章以上・各 10 秒以上」を満たさないときは注意が出ます)。
- **字幕ファイル(SRT)**: 各シーンの「字幕」に自分で書いた文を、そのシーンの時間に並べた字幕ファイルを書き出します(YouTube などに上げられます。文を自動で作ることはしません)。

### 保存と安全のしくみ

- **下書きの自動保存**: 保存していない変更はブラウザの中(localStorage)に自動で残ります。保存せずに閉じても、次に開いたときに「復元する / 捨てる」を選べます。下書きはそのブラウザにだけ残ります。
- **保存の履歴**: 保存するたびに、その前の版が `projects/.history/<名前>/` に残ります(最新 30 件)。「保存の履歴から開く」で戻せます。
- **削除**はファイルを消さず `projects/.trash/` に移します(履歴も一緒に移ります)。手で戻すこともできます。
- **zip に書き出す / 読み込む**: プロジェクトと使っている画像を 1 つの zip にまとめ、別の PC に移したり人に渡したりできます。読み込むとき、同じ名前で中身の違う画像があれば名前を付け直します。

### 書き出し

- **書き出す**: 形式と画質を選んで「書き出す」。書き出しは**順番待ち**に入り、1 つずつ順に行います(書き出し中でも次を追加できます)。上部に進み具合と残り時間の見込みが出て、押すと「書き出しの一覧」(中止・取り消し・ダウンロード)が開きます。書き出したファイルは `out/` にも保存されます。

  | 形式 | 大きさ | 内容 |
  |---|---|---|
  | 720p | 1280×720 | 標準 |
  | 1080p | 1920×1080 | 720p の画面を 1.5 倍の解像度で撮る(文字や図形はぼやけない) |
  | 縦長(ショート) | 1080×1920 | 横長の動画を中央に置き、上にタイトル、下に今の章と進み具合を出す |
  | GIF(選んだシーン) | 640×360・15fps | 選んでいるシーンだけを、くり返し再生する GIF にする |

  | 画質 | 内容 |
  |---|---|
  | 軽い | ファイルが小さい(共有向け) |
  | ふつう | 標準 |
  | 高画質 | ファイルが大きい(保存・再編集向け) |

- **まとめて書き出し**: 「ツール」→「まとめて書き出し」で、複数のプロジェクト × 複数の形式を一度に順番待ちに入れられます(編集中のプロジェクトは今の内容、ほかは保存してある内容)。
- **PNG**: 右列の「🖼 PNG」で、選んだシーンの見どころを 1 枚の画像で書き出します(サムネイルや資料に)。

### 動画全体の設定(右列の「動画全体」タブ)

| 項目 | 内容 |
|---|---|
| テーマ | ネイビー(標準)/ ライト / ブラック / フォレスト。全部品の色がまとめて変わる |
| 章の表示 | 右上に今の章(見出し)、下の端に章ごとの進み具合を出す |
| チャンネル名・ロゴ画像 | 右上とエンドカードに出す |
| エンドカード | 最後に 4 秒の締めの画面(文・チャンネル名・ロゴ)を付ける |
| シーンの切り替え | 各シーンの終わりの消え方: 左へ流れる / フェード / ワイプ / ズーム / 動きなし |

### 画像

ロゴや画像の部品で使う画像は `projects/assets/` に入ります。入力欄の「画像を追加」から選ぶと、そこにコピーされます(PNG / JPEG / GIF / WebP、10MB まで。SVG は使えません)。フォルダに直接入れても使えます。
「ツール」→「画像の管理」で、画像ごとに使っているプロジェクトを確かめ、使っていない画像を削除(`.trash` へ移す)できます。

## プロジェクトファイル

1 本の動画 = `projects/<名前>.json` の 1 ファイルです。エディタで保存すると書き出されます。手で書いても構いません。

```json
{ "title": "ブロックチェーン",
  "settings": { "theme": "navy", "chapters": false, "channelName": "", "logo": "", "endCard": false, "endCardMessage": "ご視聴ありがとうございました" },
  "scenes": [
    { "part": "bullets", "seconds": 5.5,
      "props": { "heading": "ブロックチェーンとは", "items": ["取引の記録を[[ブロック]]にまとめる"] } }
  ] }
```

- `part` は部品のフォルダ名、`seconds` は 1〜60 秒、`props` は部品の入力項目です。`settings` は省略でき、省略すると既定値になります。
- `props` に足りない項目や不正な値があっても、部品の既定値で補って表示します(エディタの右列に注意が出ます)。

## 原稿から 1 コマンドで動画にする

エディタを開かずに、原稿の Markdown(「文章からシーンを作る」と同じ書き方)から MP4 を作れます。ほかのアプリや Claude Code のスキルから動画を自動で作るための入口です。

```bash
npm run make -- 原稿.md --images 図のフォルダ --theme light --quality light --out out/今日の動画.mp4
```

1. 原稿をシーンに変換します(部品の上限を超えたところは切り詰めて知らせます)。
2. 画像のシーン `![説明](ファイル名)` のファイルを `--images` のフォルダ(省略すると原稿と同じフォルダ)から `projects/assets/` に入れます。**SVG はそのままは使わず、ブラウザで白い背景の PNG にしてから入れます**(SVG の中のスクリプトは動きません)。
3. 各シーンの見どころを撮って、文字のはみ出しを調べます。はみ出しがあれば **MP4 を作らずに終了コード 2** で終わるので、原稿の文を短くしてやり直します。
4. MP4 を書き出します。

| オプション | 内容 |
|---|---|
| `--images <フォルダ>` | 画像を探すフォルダ |
| `--format` | `720p`(既定)/ `1080p` / `vertical`(縦長) |
| `--quality` | `light` / `normal`(既定)/ `high` |
| `--theme` | `navy`(既定)/ `light` / `black` / `forest` |
| `--chapters` | 章の表示を付ける |
| `--out <ファイル>` | 書き出す MP4(既定: `out/<原稿の名前>.mp4`) |
| `--project <ファイル>` | 変換したプロジェクト JSON も保存する(`projects/` に置けばエディタで直せる) |
| `--check-only` | はみ出しを調べるだけ |
| `--allow-overflow` | はみ出しがあっても書き出す |
| `--json` | 結果を JSON 1 行で出す(`ok`・`out`・`bytes`・`seconds`・`notes`・`issues`) |

プロジェクト JSON を渡すこともできます(`--theme` などは JSON の設定を上書きします)。
SVG を PNG にするときは書き出しと同じ Chrome を使います(環境変数 `REMOTION_BROWSER_EXECUTABLE`、なければ Remotion がダウンロードした Chrome Headless Shell。一度も書き出したことがなければ、先に何か 1 本書き出してください)。

原稿の書き方のこつ(はみ出しにくくする):
- 箇条書きの 1 項目は 25 文字くらいまで、見出しは 20 文字くらいまで。
- `> 字幕` が出るのは、画像・流れ図・縦のステップ・年表・表・グラフ・コード・アイコン一覧だけです(箇条書き・まとめ・タイトルには出ません)。40 文字くらいまで。
- `Q:` / `A:` は、ほかの箇条書きと同じ `##` に入れず、専用の `##` を作る(同じ `##` にあると Q&A のシーンだけになる)。
- 2 列の表は「比較」、3 列以上は「表」になります。用語の一覧は `- [[用語]]:説明` の箇条書きにします。

## 部品の足し方

```bash
npm run new-part -- step-list ステップ一覧
```

で `src/parts/step-list/index.tsx` ができ、エディタの一覧とフォームに現れます。本体のコードは変えません(フォルダを置くだけで自動で登録されます)。各部品が公開するのは `meta`(名前・説明・秒数)、`schema`(zod の入力項目)、`Component`(props と frame から描く)の 3 つだけです。

決まり(フレームだけで見た目を決める、色や動きは `src/kit/` を使う など)・kit の使い方・確認手順は **[PARTS_GUIDE.md](PARTS_GUIDE.md)** にまとめています。AI に部品の追加を頼むときも、このガイドを読ませてください。

## フォルダ構成

```
src/
  kit/        部品用の共通ライブラリ(テーマ・フォント・動き・はみ出し対策・見出し・字幕・背景・画像・コードの色分け)
  parts/      部品(1 フォルダ = 1 部品。自動登録)と、schema から確かめ用の入力を作る samples.ts
  video/      プロジェクトの形、1 本の動画として描くコンポーネント、縦長、章、秒数の目安
  remotion/   Remotion(書き出し・Studio)の入口と書き出しの形式
  editor/     エディタ画面と部品の見本ページ
server/       プロジェクトの読み書き・履歴・画像・書き出し(Vite の開発サーバーに組み込む API)
scripts/      render / make / stills / stress / visual / new-part / start(start.bat から呼ぶ)
test/         単体テストと見た目の基準の画像(test/visual/)
e2e/          エディタの自動操作テスト(Playwright)
projects/     プロジェクト JSON と画像(assets/)。.history/ と .trash/ は Git 管理外
```

## CI(自動テスト)

GitHub に push すると、GitHub Actions(`.github/workflows/ci.yml`)が **Windows と Ubuntu** で次を実行します。

1. `start.bat --check`(Windows のみ。起動の手前までを確かめる)
2. `npm run check`(型チェック・lint・単体テスト)
3. `npm run stills -- sample` と `はみ出し確認` の静止画の書き出しと、はみ出しの自動検査
4. `npm run stress`(全部品の最大・最小の入力でのはみ出しの検査)
5. `npm run visual`(Ubuntu のみ。見た目が基準から変わっていないか)
6. `npm run e2e`(エディタの自動操作テスト。画面操作と MP4・PNG の書き出しまで)

書き出した静止画・差分の画像・自動操作テストの結果(失敗したとき)は、実行結果のページの「Artifacts」からダウンロードして見られます。

## しくみのメモ

- エディタは Vite、書き出しは Remotion のバンドラ(webpack)で同じ `src/video/ProjectVideo.tsx` をビルドします。部品の自動登録は、Vite では `import.meta.glob`、webpack では `require.context` で行います(`src/parts/modules.ts`)。Node(コマンドやテスト)では `server/parts-node.ts` がフォルダを見て読み込みます。
- 書き出しのバンドルは `src/` か `projects/assets/` が変わったときだけ作り直します。
- 書き出し中に使う文字のフォント(Noto Sans JP・JetBrains Mono、`@fontsource` から読み込み)が読み終わるまで撮影を待つので、ネットにつながっていなくても文字化けしません。
- テーマは `src/kit/theme.ts` の `colors` が今のテーマの色を返すしくみで、部品のコードを変えずに切り替わります。
- API は `127.0.0.1` だけで待ち受け、別のサイトからの書き込み要求(Origin が違う・Content-Type が JSON でない)は断ります。プロジェクト名・画像のファイル名・書き出したファイル名は、フォルダの外を指せない文字だけを受け付けます。
