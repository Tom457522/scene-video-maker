# AIエージェントに無人で仕事を任せるための5つの守り:調査レポート

> この文書は、Obsidian のセカンドブレイン(Vault)に集めた YouTube の要約・AI ニュースの記事・論文のメモと、そこから育てた Permanent Note をもとにまとめたレポートです。動画メーカーで解説動画を作るための元資料として使います。Claude Code・Agent SDK のバージョンや機能は 2026年11月時点のリリースノートの記載によります。紹介動画の内容は投稿者の説明で、公式資料での裏づけは取れていない部分があります。

## 要約

AI エージェントに、人が見ていない時間に決まった仕事をさせる(無人ジョブ・外ループ)人が増えています。筆者の Vault でも、**毎晩22時13分**の記録の取り込み、**毎週土曜19時37分**のノートの手入れ、**毎週日曜8時43分**のおすすめ作業、毎朝の AI ニュースのまとめの、**4つの自動実行**が動いています。

ところが、任せきりにすると「どこで止まるのか」「失敗したら気づけるのか」を自分で把握していない状態になりがちです。集めた資料を整理すると、無人ジョブを安心して任せるための守りは、次の**5つ**にまとめられます。

1. **止まる条件を持たせる**(回数・費用の上限、人間の承認)
2. **失敗を見える形で返す**(終了コード・結果メッセージ)
3. **外から来た文を区切って渡す**(プロンプトインジェクション対策)
4. **作った本人に採点させない**(別の目と合否の決まった証拠で確かめる)
5. **記憶は要約より生の記録を残す**(根拠を取りこぼさない)

## 1. 外ループとは何か

AI の自動化は、2つの軸で整理できます[^1]。

| 軸 | 2つの型 | 違い |
|---|---|---|
| フィードバック | 開ループ / 閉ループ | 閉ループは「作成→評価→修正」を回して品質を上げる |
| 起動のしかた | 内ループ / 外ループ | 外ループは定期実行や Webhook で、外から AI を自動で動かす |

- 外ループの起動手段は、決めた日時に起動する「**定期実行**」と、エラーなどを検知して起動する「**イベント監視**」の2つ。
- 単発の作業には外ループは要らない。週次レポートやエラー監視のような**繰り返しの作業**に使う。
- 正解が決まらない作業(例:キャッチコピー)は、無理に閉ループにしなくてよい。

## 2. 守り1:止まる条件を持たせる

外ループの設計の要は**3つ**とされています[^1]。

- **起動タイミングの制限**:まとめて処理する。何度も起動しない。
- **停止条件**:回数や費用の上限、人間の承認。
- **引き継ぎ先**:進捗メモをファイルに残し、次の実行が続きから始められるようにする。

修正を繰り返させる場合も、ループを止める決まりが必要です[^4]。

- **3回**直しても通らなければ、作り方そのものを見直させる。
- 2回目以降は**直前の修正分だけ**を見て、既出の指摘は繰り返さない。
- 動画を作るループは**5ラウンド**で止める。

## 3. 守り2:失敗を見える形で返す

人が見ていないジョブでいちばん困るのは、「**失敗したのに成功に見える**」状態です。Claude Code と Agent SDK の最近の更新は、失敗を**終了コードや結果メッセージとして外に返す**方向にそろっています[^2]。

| 合図 | 内容 | 入った版 |
|---|---|---|
| 終了コード1 | ディスクやクォータの不足でトランスクリプトを保存できないとき | Claude Code 2.1.317 |
| ログインの期限 | JSON の結果に `credential_expires_at`、期限の**10日前**から警告 | Claude Code 2.1.318 |
| 終了コード1 | 安全確認が使えず拒否されたとき | Claude Code 2.1.319 |
| 許可待ちで固まらない | 権限確認で止まる呼び出しを拒否して続行する設定 | Claude Code 2.1.319 |
| フックの失敗で止める | `onFailure: "block"` | Agent SDK |

筆者は、まず「**ログインの期限を見て、切れる前に通知する**」ところから始める方針にしました。

## 4. 守り3:外から来た文を区切って渡す

Web ページやメールなど、外から来た文には「この指示に従え」という命令が紛れ込むことがあります(**プロンプトインジェクション**)。ツールの説明に悪意のある指示を仕込む**ツールポイズニング**という脅威もあります[^3]。

- 考え方の土台は**ゼロトラスト**の**3原則**:「明示的に検証する」「最小権限にする」「侵害を前提にする」。
- 対策の一つが、AI への入力で**信頼できない情報を明確に区切る**こと(Microsoft の「スポットライティング」など)。
- ほかに、ジョブごとに使えるツールを許可リストで絞る、サンドボックスで作業フォルダの外を触らせない、という方法もあります。

筆者は、まず「外から来た文を区切って渡す」ところから入れる方針にしました。

## 5. 守り4:作った本人に採点させない

エージェントは「完了した」と言っても、頼んだことを取りこぼします。作った本人ではなく、**文脈を持たない別のエージェント**と、**合否の決まった証拠**で確かめます[^4]。

- **作る前**:計画を詰める担当(「象」)と、会話を一切知らずに計画とコードだけを見る担当(「金魚」)に分ける。金魚は会話を見られないので、言いくるめられない。
- **作っている最中**:テスト結果や画像の比較など、できた証拠を示させる。要件から合否の決まる固定のテスト(eval)を作り、通るまで完了にさせない。
- **リスクに合わせる**:「壊れたとき利用者に何が起きるか」で、低・中・高の**3段階**に分け、高リスクほど厳しく確かめる。
- 最終判断は人間。レビューは指摘が多めに出るので、役立つものだけ採る。

## 6. 守り5:記憶は要約より生の記録を残す

エージェントに過去のことを覚えさせるとき、要約して保存したくなります。しかし論文「素朴な RAG は複雑なエージェント記憶に負けない」では、逆の結果が出ています[^5]。

- 会話の生の履歴を、検索して並べ替えるだけの単純な方法(**Raw-RAG**)を、複雑な記憶の手法と比べた。
- **4つ**のベンチマーク、**7つ**の設定のうち**6つ**で Raw-RAG が1位。最強の比較手法を **0.13〜5.53ポイント**上回った。
- 理由は、必要な根拠を取りこぼしにくいこと。要約した記憶では、生の情報との差が残る。
- 注意:比べたのは会話のタスク。ジョブの実行ログやコードの変更履歴でも同じかは確かめられていない。

## 7. まとめ:任せるほど「止まり方」を知っておく

| 守り | ひとことで | まず何をするか |
|---|---|---|
| 止まる条件 | 回数・費用・承認で止める | 自動実行ごとに「起動・停止・引き継ぎ」が手順に書かれているか確かめる |
| 失敗を返す | 黙って失敗させない | ログインの期限を見て、切れる前に通知する |
| 入力を区切る | 外の文は命令として読ませない | Web・メールを読むジョブを洗い出す |
| 別の目で確かめる | 本人に採点させない | 合否の決まった証拠を示させる |
| 生の記録 | 要約より元の記録を引く | 共有メモリに元の記録を残して検索できるようにする |

AI に任せる範囲が広がるほど、「どこで止まるか」「失敗したらどう分かるか」を人間が知っている状態にしておくことが大切です。
